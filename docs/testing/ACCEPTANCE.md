# 人工验收自查（ACCEPTANCE）

> 回答一个问题：**人坐到界面前，怎么确认「需求没漏、启动不报错、界面没歪」。**
> 自动化能证明「断言过」，证明不了「用起来对」。这份手册把两者接起来：机器能判的交机器，剩下的变成一张能逐条勾的表。
>
> 配套：[TESTING](TESTING.md)（分层与门禁）、[TEST-CASES](TEST-CASES.md)（用例编号）、[CONSTRAINTS](../../CONSTRAINTS.md)（数值单一来源）。

## 0. 三道关与出口条件

| 关       | 手段                                                            | 命令                            | 出口条件               | 耗时   |
| -------- | --------------------------------------------------------------- | ------------------------------- | ---------------------- | ------ |
| 1 门禁关 | typecheck / lint / 覆盖率 100% / 改动行覆盖率 / 依赖审计        | `pnpm check`                    | exit 0                 | ~90s   |
| 2 启动关 | 冷启动 / 重载 / 二次冷启动零异常；打包产物冒烟                  | `pnpm e2e`、`pnpm e2e:packaged` | 全绿                   | 分钟级 |
| 3 界面关 | 七类几何判据（对齐 / 溢出 / 遮挡 / 点击目标）+ 本文件 §4 走查表 | `pnpm acceptance:ui` + 人工走查 | 报告 0 条 + 走查表全勾 | ~15min |

一条命令跑完 1+2：`pnpm acceptance`。第 3 关的机器部分单独跑，因为它要遍历 13 屏、比全量 e2e 慢。

**只改 UI 时**：`pnpm check:fast`（秒级）+ `pnpm acceptance:ui`（分钟级），不用等全量 e2e。

## 1. 需求完整性：靠矩阵，不靠记性

判定规则一句话：**每个用户可感知的能力点，必须落在「e2e 真实界面 / 单测 / 人工走查」三者之一；三处都没有 = 缺口。**

矩阵的权威来源是 `docs/specs/*` 的条目，用例编号在 [TEST-CASES](TEST-CASES.md)。下表只记「覆盖到哪一层」与「人该点哪一下」。

| 功能域           | 覆盖判定                                                     | 人工必点                                                                           |
| ---------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 外壳与 app 切换  | e2e 标签/顺序/默认 app；跟随系统、托盘仅手动                 | 亮→暗→跟随系统各切一次，重启看是否保持；关窗看托盘能唤回                           |
| 番茄钟           | e2e 计时主路径 + 配置钳制；铃声/系统通知/4 轮长休仅手动      | 四段时长设 1 分钟走满 4 轮；阶段结束听铃声、看通知归属                             |
| 项目             | e2e 切换与看板/会话联动；CRUD 与原生文件夹选择器仅单测       | 「+」新建 → 系统对话框先取消一次 → 保存 → 建任务 → 删有任务的项目看拒删            |
| 运行时管理       | 弹窗开合 e2e；探测 / 检测清单 / 健康 / 停用仅单测            | 点「测试」看耗时与版本；命令改错看「不可用」+ 原因；停用后派活看报错               |
| 智能体管理       | 编辑超长提示词弹窗 e2e；新建 / 拖拽排序 / 删除约束仅单测     | 新建时不可用运行时是否禁用并给原因；拖顺序后聊天默认智能体是否跟着换               |
| 工作流与阶段编辑 | 空白创建 + 行排序 e2e；**全部字段仅单测**                    | 选一条 SOP → 改一阶段为「执行脚本」→ 保存 → 重开看回填；闸门判定者不能选被验智能体 |
| 看板与任务流转   | 列渲染 / 归档条 / 两种新建 / 进详情 e2e；**卡片拖拽仅单测**  | 拖卡换列、拖到归档条、执行中的卡拖不动、查看归档点行进详情                         |
| 任务详情与审批卡 | 审批卡作答 + 反馈 e2e；四个动作 / 评审面板 / 导出仅单测      | 运行中点「停止执行」；「完成任务」禁用提示；「提升为文档」去项目目录看文件         |
| 聊天             | 一轮闭环 e2e；停止 / 第二轮续接 / 删归档会话仅单测           | 连发两轮看第二轮是否只带新消息；发送中点停止；删会话看级联                         |
| 线程与交接       | 线程页动作 + 派单/派生的内核链路 e2e；**界面触发派单未走过** | 用界面完成一张配了派单的卡，去目标工作流看新工单与来源标记                         |
| 规则自动化       | 新建 + 事件建任务 + 去重 e2e；启停/立即运行/cron 到点仅单测  | 建 `* * * * *` 等 1 分钟；停用后再等 1 分钟确认为零                                |
| 插件与设置       | webhook 全链路 e2e（经桥写配置）；**插件页 UI 操作仅单测**   | 插件页开 webhook、勾 `net`、填端口/secret → 重启 → 发签名 POST                     |
| 执行产物与导出   | 仅单测 + 手动                                                | 打开 `%APPDATA%\workbench\artifacts\threads\<id>\index.md` 核对那一轮              |
| 崩溃恢复与启动   | 强杀恢复 e2e；单实例锁 / 只读导出 / 托盘仅手动               | 执行中强杀 → 重开看任务可拖、残留 CLI 进程被清；开第二个实例被拒                   |

**当前 10 条缺口**（只有单测、真界面一次没点过，按风险排序，也就是 §4 走查表的来源）：

1. 看板卡片拖拽（换列 / 归档 / 执行中不可拖）
2. 工作流编辑器的全部字段（类型收敛、出口表、闸门验收、脚本块、单轮超时）
3. 运行时管理的真机行为（探测、检测清单、健康、停用）
4. 任务详情的四个动作 + 评审面板 + 导出
5. 项目 CRUD + 原生文件夹选择器
6. 聊天的轮次控制（停止 / 第二轮 / 删归档）
7. 插件页 UI（授权、secret 只写不回显）
8. 规则页其余动作 + cron 到点
9. 智能体管理的其余面（新建、拖拽排序、删除约束）
10. `notice` 类通知卡的合并与打扰收敛

## 2. 启动关：机器覆盖三条路径

`tests/e2e/startup.spec.ts` 逐条断言「零未捕获异常、零控制台 error、零兜底页、零页面错误条、主进程存活」：

1. **冷启动**：全新 userData → 建库、建投影、渲染首屏；
2. **重载**：`reload()` 重跑整条渲染启动链（preload 注入、shell 装配、订阅重建）；
3. **二次冷启动**：同一份 userData 再开一次——老库补列、`KERNEL_VERSION` 指纹变化触发投影重建、单实例锁、残留 pid 对账都在这一条里，**这是最容易坏、也是单测和打包冒烟都覆盖不到的一条**。

它顺带守住一个隐性故障：视图读失败时页面只显示空态（「还没有项目」「尚无工作流」），用户会以为数据丢了。错误条带 `role="alert"`，所以「没有任何 alert」等价于「视图读没失败」。

打包产物另跑 `pnpm e2e:packaged`（进程内 `node:sqlite`、单实例锁）。

## 3. 界面关：几何审计 + 人眼

### 3.1 机器能判的七类

`tests/e2e/ui-geometry.spec.ts` 遍历 13 屏（看板 / 聊天 / 任务详情 / 设置五栏目 / 三个弹窗 / 番茄钟 / 窄窗 900×640），按七类判据断言：

| 判据             | 抓什么                                                        |
| ---------------- | ------------------------------------------------------------- |
| `h-scroll`       | 整页出现横向滚动                                              |
| `offscreen`      | 元素越出视口且滚不到（弹窗被裁、按钮掉到窗外）                |
| `clipped`        | 被 `overflow:hidden` 祖先切掉（滚也滚不到）                   |
| `row-misaligned` | 横向 flex + `align-items:center` 的行里，子元素垂直中心线不齐 |
| `overlap`        | 两个文档流里的可交互元素互相遮挡（点不到 / 点错）             |
| `text-overflow`  | 文本撑出容器，压到相邻元素上                                  |
| `tiny-target`    | 可交互元素小于 20×20（点不准）                                |

报告落 `.scratch/acceptance/ui-geometry.md`：按屏分组、逐条给元素路径与差值（例如「垂直中心线相差 3px（214 / 217）」）。断言失败时报告已经落盘，直接打开看是哪一屏哪一行。

用例开头有**审计器自检**：注入四个已知缺陷的探针，四类判据必须全部报出来。没有这一步，「零问题」既可能是界面干净，也可能是检测失效。

**本轮审计抓到并修掉的**：弹窗右上角关闭按钮的点击区只有 16×16（上游 shadcn 默认，图标多大按钮就多大），`tiny-target` 报出；`dialog.tsx` 加 `-m-1.5 p-1.5` 扩到 28×28，图标视觉位置不变。

### 3.2 人眼还要看的（机器不判）

- hover / focus / disabled 三态的观感（几何审计只量静止态）；
- 动画中间态（`animate-rise`、面板展开）；
- 真实长内容（200 字标题、10 个标签、超长提示词）下的换行与截断；
- 字重与字阶的层次感（`check:ui` 只拦越界值，不判「这屏看着乱」）；
- 交互手感：点击区域、拖拽反馈、滚动惯性、弹窗关闭路径。

### 3.3 对齐的判定标准（写死，避免「我觉得歪了」扯不清）

- 同一行（横向 flex）元素的垂直中心线差 **≤ 1px**；
- 同一列的卡片、字段、按钮左边缘一致；
- 间距是 4 的倍数，同类元素用同一档（列表行 12–16、面板内边距 12–20）；
- 弹窗完整在视口内，超高时字段区自滚而不是整块被裁；
- 窗口缩到 900×640 不出现横向滚动，看板列横向滚而不是被压扁。

## 4. 30 分钟人工走查表（按顺序，一条一勾）

前置：`pnpm acceptance` 全绿；用**自己的真实数据**（不是空库），因为空态掩盖布局问题。

| #   | 屏 / 动作                              | 通过标准                                                                                 |
| --- | -------------------------------------- | ---------------------------------------------------------------------------------------- |
| 1   | 冷启动 → 首屏                          | 3 秒内出界面，无白屏、无报错条、无「界面出错了」                                         |
| 2   | 设置 → 运行时：点「测试」、改错命令    | 有耗时与版本；错的给「不可用」+ 原因，不是静默失败                                       |
| 3   | 设置 → 智能体：新建、拖顺序、删除      | 不可用运行时禁用并给原因；拖完回聊天看默认智能体是否跟着换；被引用时拒删且文案说清先改哪 |
| 4   | 设置 → 工作流：SOP 模板 → 改脚本阶段   | 字段随类型收敛；保存 → 重开回填一致；闸门判定者排除被验智能体                            |
| 5   | 看板：拖卡换列 / 拖到归档 / 拖执行中卡 | 换列并置顶；归档计数 +1；执行中的卡拖不动且无落点高亮                                    |
| 6   | 看板：列内「+ 新建任务」、窄窗         | 回车即建、失败就地报错；900×640 下横向滚不被压扁                                         |
| 7   | 任务详情：停止 / 重新执行 / 完成任务   | 停止后卡片收起、任务可再拖；禁用态给原因（title 或文案）                                 |
| 8   | 任务详情：评审面板 → 提升为文档        | 项目 `docs/reviews/` 下出现 `<slug>-<taskId8>-r<rev>.md`                                 |
| 9   | 任务详情：审批卡作答                   | 选一行 + 补充说明 → 提交；提交后卡消失、会话续接                                         |
| 10  | 聊天：两轮、停止、删会话               | 第二轮只带新消息；停止后输入区可用；删会话消息级联                                       |
| 11  | 线程：完成配了派单的卡                 | 目标工作流出新工单（带来源标记）+ 新线程                                                 |
| 12  | 规则：`* * * * *` 等 1 分钟 → 停用     | 到点自动建任务；停用后不再建；「立即运行」可用                                           |
| 13  | 插件：开 webhook、填端口/secret → 重启 | 重启后监听起得来；带签名 POST 建任务；secret 不回显                                      |
| 14  | 外观：亮 / 暗 / 跟随系统 + 关窗驻留    | 整窗配色立刻变、重启保持；关窗后托盘能唤回                                               |

勾完还发现的，按 §5 记；勾不动的（例如本机没装某个 CLI），在验收记录里写「未验 + 原因」，不要留空。

## 5. 缺陷怎么记

一条缺陷至少四行，否则改的人还得回来问：

```
屏幕 / 路径：任务详情 → 反馈框
判定标准：同一行元素垂直中心线差 ≤ 1px（§3.3）
实际：复选框与「同时让智能体接着做」文字中心线差 3px
复现：打开任意任务详情 → 滚到反馈框
```

能进自动化的就补进去：几何类问题写进 `ui-geometry.spec.ts` 的场景，交互类写进对应 `tests/e2e/*.spec.ts`，规则类先写失败用例再改实现（见 [TESTING](TESTING.md)「何时写哪层测试」）。

## 6. 命令速查

| 命令                                                           | 用途                                          |
| -------------------------------------------------------------- | --------------------------------------------- |
| `pnpm acceptance`                                              | 门禁关 + 启动关（= `check && e2e`）           |
| `pnpm acceptance:ui`                                           | 只跑界面几何审计（含构建），改完 UI 用        |
| `pnpm acceptance:startup`                                      | 只跑启动健康三路径                            |
| `pnpm check:fast`                                              | 秒级：类型 / lint / floor / secrets / ui 规则 |
| `pnpm e2e`                                                     | 全量 e2e（含启动与几何审计）                  |
| `pnpm e2e:packaged`                                            | 打包产物冒烟                                  |
| `pnpm exec playwright test tests/e2e/ui-geometry.spec.ts --ui` | 逐屏调试几何审计                              |
