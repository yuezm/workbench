# 个人AI工作流

个人AI工作台：只跑 AI 自动化，不做聊天

## 目的

我想研发自己的AI工作流，如下构想

1. 做为 Worker 接收远端的任务，即多台设备可以实现执行多个任务，只是设想，可以先设计架构，但是不实现
2. 本地支持不同的运行时工具，不同的工具擅长不同的事情
3. 可以自定义工作流，以单SOP或者SOP串联来完成大型任务
4. 由一个看板来查看当前任务的执行情况，在哪个阶段，不同的阶段有哪些任务

## 定位

- **只做自动化**：入口是任务，派活单位是智能体（或脚本阶段），界面只有看板 / 任务详情 / 线程详情；侧栏是「项目 + 工作流」，内容区就是这三页。
- **不提供聊天**：没有会话清单、没有消息输入、没有聊天栏目。内核里的 `chat.*` 命令与 `conversations` / `messages` 投影仍在，只供给历史数据与重建，产品里不再产生新对话。
- **只在必须拍板时打扰**：卡片在任务详情里处理（正文、选项、关闭都在那），顶部通知条只给标题与落点，卡片的系统通知也只给标题 + 一句指引（任务完成 / 运行失败另有结局通知）；`notice` 类只知会，不弹系统通知、不发飞书。
- **飞书只推需要人拍板的卡**：只投 `kind='ask'` 且仍 open 的卡，点按钮就是答复、原消息原地改成「已记录」；`notice` 不发、不订阅入站消息、不派活、不回帖。

## 设施

### 本地运行

此App目前运行于本地，由入口派发任务

### 运行时

可以添加多个为运行时，例如可以添加 hermes agent、claude code、codex、deepSeek harness、oh-my-pi 等运行时（这些运行时都是我本地安装的 cli）。此实现可以参考 Multica 是怎么做的

### 智能体

可以添加智能体，以某个运行时做为智能体的配置，在调用智能体时，相当于在调用某个运行时。

智能体包含

1. 名称
2. 描述
3. 执行配置（运行时）
4. 能力（每次运行的时候的System Prompt）

详细的实现可以参考 Multica 是怎么做的

### 自定义的工作流

可以自定义工作流，工作流之间可以串

例如：研发工作流 待办 --> 进行中 --> 审核中 --> 已完成
例如：QA工作流 待办 --> 审核中 --> 已完成

每个工作流的阶段，可以选择

进入时

1. 进入时，不交接
2. 进入时，交给给某个智能体
3. 进入时，交接给某个用户，让用户自己决定，此时就需要人为干预审批了

完成时

1. 自动跳转到下一个阶段，例如审核中完成后，跳转到已完成
